# MP Core 0.9.1

A patch version: two additions and nothing removed. It follows [0.9.0](0.9.0.md).

Both additions were asked for by running the [Tiffin sample](https://github.com/panahister/mpcore-tiffin-sample):
nine services, two tenants. ADR-014 has the decisions.

## Moving from 0.9.0

Nothing to do. Every change is an addition; the API baseline of `0.9.0` accepts the packages.

| Change | What you will notice |
|---|---|
| `UseMPCoreWolverine` registers `WolverineTenantMessagePublisher` as `IMessagePublisher` | A message carries the tenant of the work that published it, in the header `x-tenant-id`. A single-tenant host publishes as before |
| Every handler runs `HandlerTenantMiddleware` | A handler that runs from a queue has the tenant of its message in `ITenantContext` and `TenantScope.Current`, and its audit records name it |

## New

| Package | What it adds |
|---|---|
| `MPCore.Messaging.Wolverine` | **The tenant of a message.** `WolverineTenantMessagePublisher` writes it; `HandlerTenantMiddleware` opens it for the handler, the save included. A tenant the publisher names in `MessageDeliveryContext` wins over the ambient one |
| `MPCore.Resilience.Http` | **The identity of a service.** `AddMPCoreServiceIdentity` puts a token on every request of a client: issued to the service itself (OAuth 2.0 client credentials), asked for once, kept until shortly before it expires, forgotten when it was refused, and never sent in cleartext. Works for REST and for gRPC clients |

## Documented

| Package | What it now says |
|---|---|
| `MPCore.Persistence.Timescale` | `AddCompression` orders a hypertable's compressed chunks newest first (`DESC`), and the column it takes is a name alone. It always did; its documentation did not say so, and a sample took it for oldest first |
