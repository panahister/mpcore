## New

| Package | What it adds |
|---|---|
| `MPCore.Localization` | **The list of known keys.** `IMessageCatalog.ListKnownKeys()` returns every key that has a default text, once each and ordered by key (ordinal), as `KnownMessageKey(Key, DefaultText, Placeholders, Origin)`: the neutral default text rendering falls back to, the names of its placeholders by the rule the catalog renders with, and `MessageTextOrigin.MPCore` or `MessageTextOrigin.Product`. MP Core's own keys are in the list. A key in several sources is listed once, with the text of the highest precedence. A stored translation never adds a key. It reads no database and no network and is computed once. Sources list their keys through the optional `IListableMessageTemplateSource`, which `ResourceMessageTemplateSource` implements. ADR-012, addendum of 2026-10-12 |

How to consume the list: the product exposes it through a query of its own, and its command that stores a
translation checks the key and the placeholders, because the store checks neither.

```csharp
public sealed record ListTranslatableTexts : IQuery<IReadOnlyList<KnownMessageKey>>;

public static class ListTranslatableTextsHandler
{
    public static IReadOnlyList<KnownMessageKey> Handle(ListTranslatableTexts query, IMessageCatalog catalog) =>
        catalog.ListKnownKeys();
}
```

## Known limits

| Limit | What to do |
|---|---|
| A source that does not implement `IListableMessageTemplateSource` adds no key, while `IsKnownKey` still asks it | a product source that holds default texts implements the interface |
| The list is computed once per catalog | resource files cannot change while the process runs; a source whose default texts can change is not listed again |
| An `IMessageCatalog` implemented by a product throws `NotSupportedException` from `ListKnownKeys()` | implement the member, or use MP Core's catalog |
